# GPT Research Loop

핵심 운영 문장:

> **수집은 공격적으로, 공개는 보수적으로.**

## 목적

GPT 루프는 많은 공개 자료를 빠르게 훑어 사람이 놓치기 쉬운 과거 발언·공약·표결·행동 기록을 수집 후보로 만든다.

루프는 정치인을 판정하지 않는다. "내로남불", "위선", "좋은 후보", "나쁜 후보" 같은 결론을 생성하거나 점수화하지 않는다.

## 실행 방식

현재 기본 모드는 **수동 실행**이다.

사용자가 루프 실행을 요청하면 지정된 순서의 정치인을 조사하고, 조사 결과를 GitHub에 먼저 기록한다. Floot에는 매 회차 결과를 즉시 밀어 넣지 않는다.

조사는 다음 회차가 이전 회차의 미해결 단서를 이어받는 방식으로 진행한다.

1. 기존 GitHub 기록 확인
2. 아직 빈 영역과 미해결 단서 식별
3. 1차 자료 우선 심층 검색
4. 새 기록·출처·반론·맥락 추가
5. 중복 제거
6. 비교 가치가 있는 관계를 candidate로 기록
7. 다음 회차에서 이어갈 단서 남기기

## 중립성 규칙

모든 추적 대상에 같은 검색 규칙을 적용한다.

- 정당·이념에 관계없이 같은 출처 우선순위 사용
- 모순 가능성이 있는 기록만 찾지 않고 일관성을 뒷받침하는 기록도 함께 수집
- 상대 진영의 주장만으로 사실 확정 금지
- 공식 원문과 1차 자료 우선
- 1차 자료가 없을 때만 신뢰할 수 있는 2차 보도를 보조적으로 사용
- 날짜·인용·URL·문맥을 추정해서 채우지 않음
- 서로 충돌하는 자료가 있으면 한쪽을 지우지 말고 충돌 자체를 기록

## 저장 위치

수동 조사 결과의 기준 저장소는 GitHub다.

- `data/presidents.json`: 대통령 임기 순서
- `data/evidence/<politician>.json`: 인물별 증거 원장
- `docs/`: 조사 방법론과 운영 규칙
- `sql/`: Floot/DB로 반영할 준비가 된 마이그레이션과 seed

## Floot 반영

Floot 자동 연구 루프는 현재 비활성화한다.

충분한 기록이 쌓인 뒤 여러 회차의 결과를 한 번에 반영한다. Floot는 조사 엔진이 아니라 공개 UI, 검색, 필터, DB 기반 탐색을 제공하는 빌드·배포 계층으로 취급한다.

## 상태 흐름

web research
→ GitHub evidence ledger
→ source/context review
→ comparison candidate
→ accumulated batch
→ Floot DB/UI build
→ human review
→ published comparison

중간 검토 단계를 건너뛰고 검색 결과를 공개 페이지에 직접 올리지 않는다.
