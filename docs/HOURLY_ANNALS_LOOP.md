# Hourly Korean Politician Annals Research Policy v2

> v2 핵심: **숫자 채우기보다 정보가치, 독립 provenance, 정치인 승격, 책임관계 분해, 데이터 통합 완결성을 우선한다.** 대량채굴은 유지하되 정량 목표는 종료조건이 아니라 경고선·진단지표로 사용한다.

## 목적

최종 목표는 대통령만의 실록이 아니라 **대한민국 역대 주요 정치인 전체의 검증 가능한 디지털 실록**이다. 대통령 임기순 조사는 chronological backbone이지만 연구의 상위 계층이 아니다. 전체 연구 좌표는 `docs/KOREA_POLITICAL_FOREST.md`의 **시대 × 구조층** 매트릭스를 따른다.

대통령 조사에서 등장하는 총리·장관·국회의원·정당 지도부·관료·지방정치인·독립운동/정부수립기 정치인·경쟁자·협력자를 독립 정치인 노드로 구조화한다. 국회·정당·관료·사법·군·경찰·정보기관·지방정치·정치경제·노동·시민사회·언론·사회균열·외교안보도 독립 연구선으로 병행한다.

## 실행 최적화 원칙

### 1. 정보가치 우선
실행시간과 허용된 도구 호출 여력을 최대한 연구에 사용한다. 다만 문서 수·인물 수·검색 수를 채우기 위해 낮은 가치의 검색을 반복하지 않는다.

우선순위는 대체로 다음을 따른다.

`결정적 원문 확보 > 독립 provenance 교차검증 > 기존 명제 반증/축소 > 핵심 정치인 승격 > 사건 책임선 분해 > 새로운 후보 대량발견`

정량 목표를 달성해도 실행 여력이 남으면 다음 고정보가치 연구선으로 이동한다. 반대로 정량 목표를 못 채웠더라도 중요한 원문을 깊게 검증한 회차를 실패로 간주하지 않는다.

### 2. 주 연구선 + 교차검증선
매 회차는 가능하면 **주 연구선 1개**를 명시하고, 이를 검증하는 **독립 교차검증선 2~4개**를 둔다.

예:
- 주 연구선: 한미상호방위조약 협상
- 교차검증선: 한국 외무부/정부 기록, 국회 기록, 미국 FRUS/상원 기록, 당사자 기록

같은 질문의 검색어 변형이나 같은 기관의 연속 문서는 별도 연구선으로 부풀리지 않는다.

### 3. provenance 다양성
문서 개수와 provenance family 개수를 분리해 기록한다. FRUS 40건은 문서 40건이지만 미국 국무부 편찬 외교문서라는 provenance family는 기본적으로 1계열이다.

핵심 사건·주장은 가능한 경우 다음처럼 서로 독립된 계열을 붙인다.
- 한국 정부·관보·행정기록
- 국회 회의록·법안·표결
- 사법부·판결·공식 진상조사
- 외국 정부·외교·군 기록
- 당사자 개인 기록
- 동시대 언론·사회단체 기록

독립 provenance가 부족하면 확정 강도를 낮추고 다음 교차검증 표적을 lead로 남긴다.

### 4. 발견보다 승격
비대통령 정치인의 신규 발견 수보다 **연구성숙도 승격**을 더 높은 성과로 본다.

`DISCOVERED → IDENTIFIED → VERIFIED → ANNALS_ACTIVE → MATURE`

승격에는 근거 문서와 이유를 남긴다. 이름만 많이 추가하는 것보다 연결중심성이 높은 정치인 몇 명을 VERIFIED/ANNALS_ACTIVE로 만드는 것을 우선할 수 있다.

### 5. 수확체감 기반 이동
한 대통령·사건·시대를 완전히 해결할 때까지 머물지 않는다. 핵심 구조가 STRUCTURED 이상이고 남은 불확실성을 HISTORY_DEBT/open lead로 안전하게 보존할 수 있으며 추가 조사 정보가치가 급격히 낮아지면 다음 고우선순위 노드로 이동한다.

새 원문·반증 신호가 나타나면 이전 연구선으로 돌아온다.

## 정량 지표의 위치

아래 숫자는 **강제 종료조건이나 체크리스트가 아니라 대량채굴이 지나치게 얕거나 좁아졌는지 탐지하는 경고선**이다.

자료와 접근성이 충분한 일반 대량조사 회차의 참고선:
- 독립 연구선 약 20개
- 일반 국정영역 약 6개
- 비대통령 정치인 신규/심화 약 10명
- event/sub-event 신규/보강 약 8개
- 직접 확인 문서 약 40개, 공식·1차·동시대 자료 약 20개
- adversarial check 약 10개
- history-debt/open-lead 추적 약 8개
- 독립 provenance 교차검증 약 3묶음

그러나 위 수치를 맞추기 위해 이미 충분히 검증된 문서를 반복하거나, 같은 provenance의 연속문서를 의미 없이 열거나, 얕은 정치인 후보를 양산하거나, 불필요한 lead를 만들어서는 안 된다.

실행 보고에는 실제 수치를 그대로 기록한다.

## Lead budget

새로 발생한 유효 lead는 버리지 않고 기록한다. 그러나 매 회차 30개를 기계적으로 생성하지 않는다.

다음 실행의 **active queue는 원칙적으로 상위 10~15개**를 유지한다. 각 active lead에는 가능하면 다음을 기록한다.
- target institution/archive
- document/record/date/document number/person
- 해결하려는 claim 또는 관계
- expected information value
- accessibility
- graph impact
- current status: OPEN / NARROWED / BLOCKED / CONFLICTED / REOPENED

나머지는 backlog로 보존한다. 해결된 lead를 active queue에 계속 남겨두지 않는다.

## Forest-first 원칙

연구 순서는 기본적으로 다음과 같이 둔다.

`시대/체제 → 제도 → 기관 → 정치·사회 세력 → 균열/정책영역 → 사건 → 행위자 → 문서 → 주장/반증`

`대통령 → 주변인물 → 사건`만을 반복하지 않는다. 전국 coverage의 기본 단위는 `시대 × 구조층` 셀이고, 상태는 `UNMAPPED → SEEDED → STRUCTURED → VERIFIED / DEBT_TRACKED`를 사용한다.

전국 breadth가 이미 SEEDED에 도달한 영역에서는 단순 seed 추가보다 STRUCTURED/VERIFIED 승격을 우선한다.

## 매 실행 시작

1. README와 최근 commits, open issues/PRs를 확인한다.
2. `data/presidents.json`, `data/politicians.json`, registry/index, `data/events.json`을 확인한다.
3. 현재 인물 evidence/annals/open-leads/coverage를 확인한다.
4. `data/research/HISTORY_DEBT.md`, 직전 run report, active lead queue를 확인한다.
5. document/claim registry와 관련 방법론 문서를 확인한다.
6. 이미 해결된 검색을 기계적으로 반복하지 않는다.
7. 주 연구선과 교차검증선을 선정한다.

## 조사 사슬

가능한 범위에서 다음을 반복한다.

`검색어 확장 → 2차 자료에서 원문 단서 추출 → 공식/1차 아카이브 역추적 → 날짜·인물·기관·사건명 변형 → 상반 자료 탐색 → 원문 교차검증 → 새 인물/기관/사건/문서/claim 단서 생성`

한국어·영어·한자·과거 표기·로마자 변형을 활용한다. 대형 PDF나 아카이브 접근이 막히면 같은 URL을 반복하지 말고 문서명·문서번호·작성일·작성기관·색인·인용문을 확보해 대체 소장처와 인용 연구를 역추적한 뒤 다른 연구선으로 이동한다.

## 출처와 주장 강도

공식 1차 자료, 동시대 기록, 법령, 판결문, 국회·정부·대통령기록, 선거기록, 관보, 공식 진상조사, FRUS와 해외 국가기록을 우선한다. 언론·논문·전기·회고록은 원문 단서와 맥락에 활용하되 중대한 사실을 단독 확정하지 않는다.

확인된 사건, 당사자 주장, 정부/기관 행동, 동시대 관찰, 후대 판결·진상조사, 정치적·법적·행정적 책임, 직접명령을 분리한다.

신뢰 가능한 자료가 충돌하면 `CONFLICTED`, 현재 접근 가능한 원문으로 해결할 수 없으면 `BLOCKED`를 사용한다. 새 증거가 기존 기록을 흔들면 silent overwrite하지 않고 correction/review history를 남긴다.

## 정치인 중심 확장

모든 정치인은 stable ID를 가진 독립 노드다. 대통령 여부는 역할 속성일 뿐이다.

정치인 registry는 가능한 범위에서 다음을 표현한다.
- stable ID
- 이름·이명·한자·영문/로마자 변형
- 생몰과 검증 수준
- 시기별 공직·정당/정파
- 선출/임명
- event/action 연결
- research status와 승격 이유
- evidence coverage
- open leads
- history debt

중요도는 역사적 영향범위·공직 수준·제도변화 관여·주요사건 관여·자료 연결중심성으로만 관리한다. 정치적 호불호·선악·위선·영웅/독재자·추천/반대 점수를 만들지 않는다.

## 사건과 책임선

큰 사건은 필요하면 sub-event/action으로 분해한다. 가능한 경우 다음 관계를 분리한다.

- proposed_by
- decided_by
- executed_by
- opposed_by
- legal_authority
- observed_by
- later_finding

대통령 재임 중 발생했다는 이유만으로 대통령 직접 지시로 귀속하지 않는다.

## 문서·claim 그래프

문서는 재사용 가능한 1급 객체로 관리한다. 가능한 경우 문서번호, 날짜, 작성자/발신자, 수신자, 기관, 언어, 원문 위치, 원문 확보 여부, 공개상태, provenance, access date를 저장한다.

claim은 supporting / contradicting / insufficient evidence와 contemporaneous observation / later finding을 구분한다. 하나의 문서를 여러 정치인·사건·claim이 공유할 수 있게 하며 URL 중복을 줄인다.

## Consistency Gate

연구 결과를 두 상태로 구분한다.

- `RESEARCHED`: 유의미한 원문·사실·반증·관계를 확보했으나 데이터 계층 동기화가 끝나지 않음.
- `INTEGRATED`: 영향을 받는 데이터 계층이 동기화되고 참조관계가 점검됨.

실질적 연구 진전이 있으면 회차 종료 전 가능한 범위에서 다음을 검사한다.

`document → claim/evidence → event/action → politician/organization → annals/coverage → open lead/history debt`

모든 회차가 모든 계층을 수정할 필요는 없다. **실제로 영향을 받은 계층이 빠짐없이 반영되었는지**가 기준이다.

검사 항목:
1. 새 document가 document registry에 존재하는가.
2. 핵심 claim이 supporting/contradicting/insufficient evidence와 연결되는가.
3. 사건이 필요한 경우 event/action으로 연결되는가.
4. 관련 정치인 stable ID가 존재하고 사건과 연결되는가.
5. 승격 조건을 충족한 정치인의 research status와 이유가 갱신되었는가.
6. 새 증거가 기존 coverage/open lead/history debt를 바꾸는가.
7. 존재하지 않는 ID, 깨진 참조, 중복 문서/URL이 생기지 않았는가.
8. run report의 수치가 실제 파일 변경 및 조사기록과 일치하는가.

GitHub 쓰기 제한 등으로 동기화가 끝나지 않으면 완료했다고 기록하지 않고 `RESEARCHED_NOT_INTEGRATED` 또는 동등한 상태와 누락 계층을 명시한다.

## 역사부채 주간 전수조사

전체 역사부채 전수조사는 **매주 일요일 Asia/Seoul 기준 그날의 첫 조사 회차에서만** 수행한다. `OPEN`, `NARROWED`, `BLOCKED`, `CONFLICTED`, `REOPENED` 전체를 모든 등록 정치인·사건에 걸쳐 확인한다.

`last_full_review`는 마지막으로 완료한 전수조사 날짜, `last_full_review_attempt`는 완료 여부와 무관한 당일 첫 시도 날짜다. 같은 일요일에 `last_full_review_attempt`가 이미 기록되어 있으면 전수조사를 반복하지 않는다. 시도가 불완전하면 `last_full_review`는 이전 성공 날짜로 유지하고, 미검토 ID와 다음 일요일을 명시한다. 새 디지털화·기록물 해제·판결/국회/정부 추가공개·해외 외교문서·학술연구·회고록·archive access 변화를 확인한다. `RESOLVED`는 새 반증 신호가 있을 때만 `REOPENED`한다.

주간 전수조사 파일이 존재하지만 `HISTORY_DEBT.md`의 `last_full_review` 또는 상태변경이 동기화되지 않았다면 완료로 간주하지 않고 consistency audit 대상으로 둔다.

## 대통령 backbone과 이동 기준

현재 이승만 연구는 계속 심화하되 완전성 자체를 종료조건으로 삼지 않는다.

다음 대통령·시대·고중심성 정치인으로 이동할 수 있는 조건:
1. 핵심 국정영역과 주요 사건 구조가 대체로 STRUCTURED 이상이다.
2. 연결중심성이 높은 비대통령 행위자가 registry에 포착되어 있다.
3. 결정적 미해결 사항이 HISTORY_DEBT/open lead에 보존되어 있다.
4. 추가 검색의 한계정보가치가 낮아지고 있다.
5. 다른 시대/인물/구조층의 기대정보가치가 더 높다.

이동은 연구 종료를 의미하지 않는다. 새 증거가 나타나면 이전 backbone으로 돌아온다.

## Floot

Floot는 조사 데이터 계층과 분리한다. 연구 회차에서 Floot를 수정하거나 빌드하지 않는다. 충분한 데이터/스키마/UI 변화가 축적되고 사용자가 별도로 요청했을 때만 배포 계층을 다룬다.

- Consistency Gate 결과: INTEGRATED / RESEARCHED_NOT_INTEGRATED
- 실제 수정 파일
- 모든 해당 GitHub commit SHA
- 다음 최우선 연구선

정량 경고선에 못 미치면 이유를 기록하되 숫자를 만들지 않는다. 반대로 경고선을 넘겼다는 이유로 조기 종료하지 않는다.

주간 전수조사를 실행하지 않은 회차는 **역사부채 주간 전수조사 미실시**라고 명시한다.

## 인물 관계 × 발언 × 실제 행동 추적 (핵심 연구축)

정치인 실록의 최소 분석 단위는 인물 소개나 사건 이름이 아니라 **시점이 명시된 행위자-상대방-발언-행동-결과-근거의 연결**이다. 모든 고우선순위 연구선에서 가능한 경우 다음을 수행한다.

1. **발언 원장:** 발언자 ID, 날짜·장소·청중, 원문 언어·전문 위치·정확한 인용 범위, 발언 형식(공약/공식 지시/국회 발언/사적 서신/언론 인터뷰/사후 해명), 대상 인물·기관·정책, 당시 맥락을 기록한다. 간접인용·기자 해석·당사자 부인은 원문 발언과 구분한다.
2. **행동 원장:** 실제 표결·법안 발의·서명·임명·해임·예산 편성·집행·명령·거부·협상·시위 참여 등 관찰 가능한 행동을 날짜, 법적 권한, 실행자, 결과, 원문 증거와 함께 기록한다. 제안/발언과 결정/집행/성과를 동일시하지 않는다.
3. **관계 원장:** 인물 A↔B 관계를 단일 고정 라벨로 정의하지 않는다. 시기별 협력·경쟁·반대·지휘·임명·정당 동료·협상·증언·비판 등의 **유형, 방향, 시작/종료 또는 관찰 시점, 주제, 근거, 반대 근거**를 별도 edge로 기록한다. 같은 두 사람이 분야별로 협력하면서 다른 분야에서 대립할 수 있다. 혈연·사적 친분·동기는 직접 근거 없이는 추정하지 않는다.
4. **발언-행동 대조:** 같은 인물의 같은 정책·대상·시기에 관한 발언과 실제 행동을 연결한다. 일치, 불일치, 부분 이행, 입장 변경, 판단 보류를 **검증 가능한 관계 설명**으로 기록하되, 위선·진정성·선악의 자동 점수나 판정은 하지 않는다. 시간차, 권한, 제도적 제약, 정보 변화, 반대자 개입, 사후 설명을 검토한다.
5. **인물 간 교차 추적:** A의 발언에 대한 B의 반응, B의 결정에 대한 C의 집행, 반대 표결, 이후 관계 변화까지 사건·문서 ID로 연결한다. 한쪽 기록만 확보한 관계는 단일 출처/미검증으로 표시하고 상대방 원문을 adversarial lead로 만든다.
6. **시간적 인과 구분:** 선후관계나 동시 출현만으로 인과·지시·공모를 추정하지 않는다. 직접 지시, 문서상 전달, 제도적 권한, 정황적 연관, 후대 해석을 분리하고 각 연결의 증거 수준을 명시한다.
7. **데이터 호환성:** 기존 politician/event/document/claim ID를 유지하며 선택적 `statements`, `actions`, `relationships`, `statement_action_links` 또는 별도 registry를 점진 도입한다. 공통 필드는 `id, actor_id, target_ids, event_id, document_ids, occurred_at, relation_type, provenance, verification_status, contrary_evidence, open_leads`를 권장한다. 스키마 도입 전 기존 파일 구조를 확인하고 migration/참조 검사를 수행한다.
8. **승격 기준:** 인물 이름·직책만으로 심화 완료 처리하지 않는다. 최소 한 건의 원문 기반 실제 행동과 발언 또는 발언 미확보 사유, 근거 있는 타 인물과의 시점별 관계를 확보한 뒤 실록 심화를 인정한다. 자료가 없으면 누락으로 표시한다.
9. **실행 감사:** 매 회차 `새 발언 원문 / 실제 행동 / 시점별 인물관계 edge / 발언-행동 대조 / 상호 반증 검증 / 미확인 관계`를 구분하여 실제 수치를 보고한다. 발언과 행동이 동일 문서에서 함께 나와도 독립 출처 수를 부풀리지 않는다.

**연구 우선순위 보정:** 인물 간 관계가 변한 분기점, 공적 발언과 제도적 행동이 연결되는 순간, 발언과 행동의 외견상 차이를 설명할 수 있는 원문을 일반적인 인명 후보 추가보다 우선 조사한다. 일치하는 기록도 불일치하는 기록과 동일한 기준으로 수집한다.


## 검증 중심 운영 개선안 (2026-10-26 승인, 1~6항)

이 절은 기존 대량채굴 원칙을 대체하지 않고 **성과 측정·연구 배분·실록 승격·증거 평가·회차별 진척 집계**를 강화한다. 모든 비율은 실제 분모와 산출 근거가 있을 때만 계산한다. 데이터가 부족하면 `UNKNOWN`으로 남기고 임의 완성도 점수를 만들지 않는다.

### 개선 1. 양적 생산과 검증 진척을 별도 측정

매 회차 신규 문서·인물·사건·검색 수와 별도로 다음을 집계한다.

- **원문 확보율** = 원문 전체 또는 명시한 검증 대상 범위를 실제 열람한 고유 문서 / 원문 확인 대상 고유 문서. 서지·검색결과·초록만 본 경우 원문 확보로 세지 않는다.
- **핵심 주장 교차검증률** = 독립 provenance family 두 계열 이상으로 직접 대조한 핵심 주장 / 검증 대상으로 등록된 핵심 주장. 세 계열 이상 완료 수는 별도로 표기한다.
- **사건 단계 확인률** = 제안·논의·결정·명령전달·집행·결과 가운데 해당 사건에 적용되는 필수 단계를 증거로 확인한 수 / 적용되는 필수 단계 수. 단계별 미확인은 별도 표시한다.
- **정치인 연구 성숙도 분포** = DISCOVERED / IDENTIFIED / VERIFIED / ANNALS_ACTIVE / MATURE별 인원과 승격·강등 사유. 정치인의 선악이나 성과를 평가하는 점수가 아니다.
- **역사부채 실질 진척** = 해결된 질문 수, 구체적으로 좁혀진 질문 수, 재개·신규 질문 수를 별도 집계. 단순 OPEN→NARROWED 명칭 변경만으로 진척을 인정하지 않는다.
- **시대 × 구조층 검증률** = VERIFIED 셀 / 정의된 전체 셀. SEEDED와 STRUCTURED는 VERIFIED에 포함하지 않는다.
- **문서당 질문 해결 기여** = 문서가 새로 뒷받침·반박·축소한 claim/open lead ID를 중복 제거해 기록한다. 단순 평균보다 기여 ID 목록을 우선 보존한다.

분모의 포함 기준, 중복 제거 규칙, provenance 판정 기준, 집계 시점 및 집계 불가 이유를 보고서에 남긴다. 완료율은 연구 우선순위와 품질 진단을 위한 것이며 정치인 점수화에 사용하지 않는다.

### 개선 2. 연구시간 배분을 검증 중심으로 조정

초기 운영 기준은 **신규 발굴 40% / 기존 사건 심층검증·반증 35% / 역사부채 축소·독립 인물 실록 완성 25%**다. 이 비율은 고정 할당이나 종료조건이 아니다. 접근 차단, 결정적 원문 발견, 긴급 정정, 높은 기대정보가치에 따라 탄력 조정한다.

매 실행 보고에 가능하면 각 영역의 실제 작업시간을 기재한다. 정확한 시간 계측이 불가능하면 추정 시간을 사실처럼 기재하지 않고, 수행한 연구선과 작업 종류만 기록한다. 기존 대량채굴 정량 참고선은 유지하지만 수량 달성을 위해 깊이 있는 검증을 중단하지 않는다.

### 개선 3. 비대통령 정치인 독립 실록 완결성

대통령 관련 사건에 등장했다는 이유만으로 정치인 연구가 완료됐다고 보지 않는다. 주요 비대통령 인물은 자신의 생애 시기, 시기별 직책·정당·정파, 주요 정책·표결·인사·행정행위, 협력·대립 관계, 발언과 실제 행동, 결과·후대 평가, 반증과 역사부채를 독립적으로 추적한다.

`ANNALS_ACTIVE` 승격에는 독립 annals/evidence 경로, 최소 한 건의 원문 기반 실질 행동, 시점별 관계와 미해결 질문을 요구한다. `MATURE`는 사전에 정의한 해당 인물의 주요 시기·영역에 대한 coverage와 핵심 주장 검증 및 미해결 항목의 명시적 보존을 요구한다. 단순 문서·사건 수가 아닌 검증 범위와 근거로 승격하고 승격 이력을 남긴다.

### 개선 4. 사건 결정 과정 그래프

주요 사건은 가능한 범위에서 다음 순서의 단계별 action으로 분해한다.

`문제 발생 → 제안 → 논의 → 결정 → 명령·전달 → 집행 → 관찰된 결과 → 사후 평가`

각 단계에 actor/organization ID, event/action ID, 날짜·시각, 법적 권한, document ID, 증거 역할, 반대 자료, 불확실성, open lead를 연결한다. 적용되지 않는 단계는 `NOT_APPLICABLE`, 아직 확인하지 못한 단계는 `UNKNOWN`으로 구분한다. 제안=승인, 명령=집행, 재임 중 발생=대통령 직접지시, 시간적 선후=인과관계로 추론하지 않는다. 기존 ID는 유지하며 선택적 필드와 migration으로 확장한다.

### 개선 5. 문서 권위와 증거 역할 분리

모든 핵심 증거에 대해 가능하면 작성자·작성시점·수신자·작성 목적·이해관계, 직접 관찰 여부, 전언·추정·정책 제안·공식 결정·집행 확인·후대 판단 중 역할을 기록한다. **공식문서라는 이유만으로 문서 속 모든 주장을 확정 사실로 취급하지 않는다.**

동일한 최초 정보원에서 파생된 서로 다른 문서는 별개 URL·문서이더라도 독립 교차검증으로 계산하지 않는다. 문서 registry에는 `provenance_family`, 가능한 경우 `upstream_source_ids` 또는 `derived_from`, `evidence_role`, `observation_basis`를 점진 도입한다. 출처가 충돌하면 양측 근거와 정확한 충돌 지점을 보존한다. 일치하는 증거도 동일한 탐색 강도로 수집한다.

### 개선 6. 회차별 검증 대시보드와 변화 추적

매 회차 종료 시 기준 브랜치/커밋과 연구 브랜치/커밋을 명시하고, 가능하면 직전 **동일 기준·동일 분모**의 스냅샷과 비교한다. 필수 표시 항목은 등록 정치인 수, 성숙도별 인원, 독립 실록 인원, 원문 확보 문서 수/율, 핵심 주장 교차검증 수/율(2계열과 3계열 구분), 사건 단계 확인률, 역사부채 상태별 건수와 실질 진척, 시대×구조층 상태별 셀 수/검증률이다.

수치는 실제 registry와 검증 로그에서 계산하고 출처 파일 경로·집계 시각·분모 정의·검증 스크립트/방법을 기록한다. 기준이 변경되면 전후 수치를 직접 비교하지 않고 `BASELINE_CHANGED`를 표시한다. 아직 산출할 수 없는 항목은 `UNKNOWN`으로 기록하며 추정 완성도를 측정치로 제시하지 않는다. 연구 보고의 최상단에 **이번 회차에 검증된 지식이 무엇만큼 증가했는가**를 요약한다.
